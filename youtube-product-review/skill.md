# YouTube Product Review Script Writing Skill

## STEP 0 — Read Before Doing Anything

Before generating any content, analyze the input for:
- **Product name** — exact model/brand
- **Product category** — tech gadget, software, consumer electronics, lifestyle, etc.
- **Review type** — single product review, comparison (2+ products), roundup (top N), unboxing, long-term usage
- **Target audience** — beginners, enthusiasts, professionals, budget-conscious buyers

Do not skip this analysis step.

---

## STEP 1 — Analyze Input

Collect from user:
- **Product(s)** — name, brand, model, price point
- **Key features to highlight** — what makes this product stand out
- **Review angle** — honest assessment, problem-solving, value comparison, durability test
- **Duration** — e.g., "8-12 minutes"
- **Target audience knowledge level** — beginner, intermediate, expert

Then decide:
- **Review structure** → See structures below
- **Hook template** → Match from templates below
- **Comparison needed?** → Yes/No (affects structure)

## VIDEO STRUCTURES

### Structure A — Single Product Review
```
[Hook] → [Problem/Context] → [Product Intro] → [Unboxing/First Impressions] → [Feature Deep Dive] → [Real-World Testing] → [Pros & Cons] → [Verdict/Value Assessment] → [CTA]
```

### Structure B — Comparison Review (2 Products)
```
[Hook] → [Products Intro] → [Specs Comparison] → [Category 1 Winner] → [Category 2 Winner] → [Category 3 Winner] → [Overall Verdict] → [Who Should Buy Which] → [CTA]
```

### Structure C — Roundup Review (Top N)
```
[Hook] → [Quick Overview of All] → [#3 Pick] → [#2 Pick] → [#1 Pick/Best Overall] → [Budget Alternative] → [Final Recommendations] → [CTA]
```

## HOOK TEMPLATES (≤15 seconds | ≤35 words)

Must include:
1. Problem identification or curiosity gap (2–3s)
2. Solution preview or what's at stake (3–5s)
3. Value promise or why watch (5–7s)

No backstory. No "welcome back". No filler.

**Template A — Problem/Solution Hook:**
> "[Product] promises [claim], but does it actually deliver? I spent [time] testing it so you don't have to."
> Example: "This $200 smartwatch promises 7-day battery life, but does it actually deliver? I spent two weeks testing it so you don't have to."

**Template B — Bold Claim/Controversy Hook:**
> "Everyone says [product] is the best for [use case], but they're wrong. Here's what nobody's telling you."
> Example: "Everyone says the AirPods Pro are the best for workouts, but they're wrong. Here's what nobody's telling you."

**Template C — Curiosity Gap Hook:**
> "I discovered something about [product] that completely changed how I use it. And it's not what you think."
> Example: "I discovered something about this budget laptop that completely changed how I see it. And it's not the specs."

**Template D — Price/Value Hook:**
> "Why would anyone pay [high price] for [product] when this [alternative] costs [low price] and does the same thing?"
> Example: "Why would anyone pay $400 for noise-canceling headphones when these $80 ones sound nearly identical?"

**Matching rule:**
- Testing/review focus → Template A
- Contrarian take/hot take → Template B
- Discovery/unexpected finding → Template C
- Price comparison/budget focus → Template D

**Don'ts:**
- ❌ "Hey guys, welcome back to the channel..."
- ❌ "I've been using [product] for 3 years now..."
- ❌ "Before we start, don't forget to subscribe..."

## PRODUCT INTRODUCTION (20–30 seconds total)

### Order (must follow exactly):
1. Acknowledge viewer's problem/need (2–3s)
2. Introduce the product as potential solution (3–5s)
3. State the core question/promise being tested (5–7s)
4. Set expectations for the review (5–8s)

**Template A — Single Product Review:**
```
"You're looking for [solution to problem], and [Product Name] keeps coming up as the top recommendation. 

The question is: does it actually solve [specific problem] for someone like you?

Over the past [timeframe], I've put it through [testing scenarios]. No sponsored nonsense—just real testing, real results, and an honest verdict on whether it's worth your money."
```

**Template B — Comparison Review:**
```
"You're torn between [Product A] and [Product B]—and the marketing makes both sound perfect.

But here's the truth: they're built for completely different people. Choose wrong, and you're either overspending or settling for something that doesn't actually solve your problem.

Today, I'm comparing them across [categories: sound quality, battery life, price, etc.]. By the end, you'll know exactly which one is right for your specific situation—and why."
```

**Template C — Roundup/Best Of:**
```
"The [product category] market is flooded with options, and most 'best of' lists are just whoever paid the most for placement.

You need something that actually works for YOUR situation—whether that's [scenario 1], [scenario 2], or [scenario 3].

After testing [number] models across [timeframe], I've narrowed it down to the only [number] worth considering. We'll go through each one, who it's for, and why the rest didn't make the cut."
```

## FEATURE DEEP DIVE SECTION

### Structure for Each Feature Tested:
**Action + Result + Implication**

Never describe the interface. Describe what the user experiences.

**Template:**
> "When you [action], you'll notice [specific result]. This matters because [implication]."

**Example:**
> "When you enable noise cancellation on the subway, you'll notice it cuts about 80% of the rumble without that pressure sensation some headphones create. This matters because you can actually wear these for a full commute without getting that claustrophobic feeling."

### Testing Categories (adapt based on product type):

**For Electronics/Gadgets:**
1. **Performance** — speed, power, output quality
2. **Battery Life** — real-world usage vs. claimed
3. **Build Quality** — materials, durability concerns
4. **Usability** — learning curve, everyday convenience
5. **Value** — price-to-performance ratio

**For Software/Apps:**
1. **Core Functionality** — does the main thing well?
2. **Workflow Integration** — fits into existing habits?
3. **Learning Curve** — how long to proficiency?
4. **Reliability** — crashes, bugs, inconsistencies
5. **Pricing Model** — fair value for cost?

---

## VERDICT SECTION

### Structure:
1. **Who This Is For** — specific user profile(s)
2. **Who This Is NOT For** — who should skip it
3. **Value Assessment** — is it worth the price?
4. **Alternatives to Consider** — if this isn't right

**Template A — Single Product:**
```
"So, is [Product] worth it?

If you're [specific user type 1] who needs [specific capability], then yes—this is the best option under [price point]. The [key strength] genuinely sets it apart from [competitor].

However, if you're [user type who should skip], save your money. The [limitation] means you'll be frustrated within a week. For you, [alternative] is a better fit at half the price.

At [price], you're paying a [premium/fair price/budget option] for [what you get]. Whether that's worth it depends entirely on how much you value [key benefit]."
```

**Template B — Comparison Verdict:**
```
"Here's the bottom line: [Product A] and [Product B] aren't really competitors—they're for different people.

Choose [Product A] if: [3 specific criteria]. You'll get [key benefit], which matters more than [sacrifice].

Choose [Product B] if: [3 different criteria]. You're trading [sacrifice] for [key benefit], which is the right call for [use case].

The mistake most people make is [common error]. Avoid that, pick based on [decision criteria], and you'll end up with the right tool for your actual needs."
```

## CTA (Call to Action)

### Mid-Video CTA (after first major value delivery):
> "If you're finding this helpful so far, hit the like button—it helps the channel and lets me know what content to make more of. Drop a comment below if you have questions about [product] or want to see a comparison with [alternative]."

### End CTA — Product Link:
> "I'll leave a link in the description if you want to check out [Product] at its current price. That's an affiliate link, which means I earn a small commission if you purchase through it—at no extra cost to you. It helps support independent reviews like this one."

### End CTA — Subscribe:
> "If you want more honest tech reviews without the sponsored nonsense, subscribe and hit the notification bell. I publish new reviews every [frequency], focusing on products I've actually tested for at least [timeframe]."

### Alternative End CTA — Watch Next:
> "Want to see how [Product] compares to [Alternative]? Check out this video next where I put them head-to-head across [categories]. The results might surprise you."

## SEO TITLES (generate 3)

Use these formulas:
- `[Product Name] Review: [Key Finding] (2026)`
- `Is [Product Name] Worth It? [Honest Review] After [Timeframe]`
- `[Product A] vs [Product B]: Which Should You Buy?`
- `[Product] Review: The Honest Truth About [Common Claim]`

Rules:
- Lead with the product name or the review outcome
- Include year for recency (2026)
- Use numbers where relevant (price, specs, ratings)
- Under 60 characters for full visibility
- Include emotional triggers: "honest", "truth", "worth it", "don't buy"

## SCRIPT RULES

### Style
- Open with viewer's problem/curiosity, not a greeting
- Cut all filler: "hey guys", "what's up", "so anyway"
- Use "So" to transition between sections
- Short sentences. One idea per sentence.
- Use specific numbers, not vague words
- Close sections with clear takeaways

### Tone
- Objective and honest, never overly promotional
- First-person testing perspective
- Professional but conversational
- Transparent about limitations and flaws

### Content Rules
- **ALWAYS mention price** and value assessment
- **ALWAYS include at least one criticism/flaw** (no product is perfect)
- **NEVER read spec sheets** — viewers can look those up
- **ALWAYS test claims** — verify manufacturer promises
- **ALWAYS say who it's NOT for** — not everyone should buy this

---

## FEATURE ANALYSIS FRAMEWORK

For each major feature tested, answer:
1. **What does it claim to do?** (manufacturer promise)
2. **What did I actually test?** (your methodology)
3. **What happened?** (results, with specific numbers when possible)
4. **So what?** (why this matters to the viewer)

Example:
> "The company claims 20-hour battery life. To test this, I ran a continuous loop of mixed usage—music, calls, and standby. I got 18 hours and 23 minutes. So you should expect a full day of heavy use, but you'll need to charge nightly if you're a power user."

---

## REHOOK (every 60–90 seconds)

Place rehooks at:
- 1:30 — First Rehook (confirm value delivered)
- 3:00 — Second Rehook (prevent drop-off before main content)
- 4:30 — Final Rehook (guide to verdict)

**Rehook Types (rotate, don't repeat):**
1. **Progress recap** — "So far we've covered X and Y—next we're getting to the part everyone asks about..."
2. **Value preview** — "The next test changed my mind completely about this product..."
3. **Handle resistance** — "You might be wondering why I didn't mention [feature]—it's because..."
4. **Key moment** — "This next part is where most reviews get it wrong..."
