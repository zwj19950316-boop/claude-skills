# 营销工作 AI 提效诊断

## 目标
帮助营销人员梳理日常工作流程，找出可以用 AI / skill 提效的环节，输出一份可落地的诊断报告。

## 输入
用户会提供以下信息（可能不完整，缺失时主动追问）：
1. **岗位名称** — 如：社媒运营、广告投放专员、内容策划、SEO 专员、KOL 运营等
2. **日常工作内容** — 具体任务清单，最好带时间占比
3. **使用的工具/平台** — 如：Google Ads、Meta Ads、抖音、小红书、Shopify、HubSpot 等
4. **当前痛点** — 最耗时、最重复、最容易出错的环节
5. **工作文档**（可选）— SOP、排期表、数据报表、周报模板等

## 诊断流程

### 第一步：梳理工作流
将用户的日常工作拆解为具体环节。按以下维度分类：
- **信息收集** — 市场调研、竞品监测、热点追踪、数据拉取
- **策略分析** — 话题筛选、优先级排序、搜索流量分析、受众匹配
- **内容生产** — 文案撰写、脚本写作、图片/视频制作、多语言翻译
- **渠道运营** — 社媒发布、广告投放、KOL 对接、邮件发送
- **数据与复盘** — 报表制作、数据分析、A/B test、周报月报
- **沟通协作** — 跨部门对接、客户沟通、制作需求传递

**重要：时间占比不要平均分配。** 主动询问用户或根据描述推断：
- 哪个环节占用时间最多？（通常是选题/策略或内容生产）
- 哪个环节是最大痛点？（用户明确提到的优先标注）
- 哪个环节有专人负责或已外包？（时间占比应调低）

### 第二步：识别提效机会
对每个环节，判断：
- **是否高度重复？** → 适合自动化脚本或 batch 处理
- **是否依赖模板？** → 适合 AI 生成初稿 + 人工审核把关
- **是否需要大量信息整合？** → 适合 AI 汇总/分析，但关键结论需人工验证
- **是否涉及创意决策？** → 适合 AI 辅助头脑风暴和选项生成，最终决策权在人
- **是否需要跨平台操作？** → 适合 workflow automation

**关键原则：AI 是辅助而非替代。**
- 对于**选题验证、策略判断、数据分析**等需要结论的环节：AI 负责收集信息、整理选项、呈现数据，用户负责最终判断
- 对于**脚本撰写、文案生成**等创意环节：AI 负责生成初稿和模板，用户负责注入品牌调性和人性化表达
- 对于**信息收集、数据汇总**等执行环节：AI 可以承担大部分工作，用户只需抽查验证

### 第三步：匹配 skill 或给出自建方向
对每个可提效环节，按以下优先级推荐：

1. **优先推荐用户已安装的 skill**
   - 使用 `find-skills` 查找相关 skill
   - 如果找到，说明该 skill 能做什么、适用于当前哪个环节

2. **其次推荐 GitHub 上公开的技能包**
   - 搜索 `github.com` 或 `claude.ai/skills` 上相关的社区 skill
   - 给出 skill 名称、一句话功能描述、适用场景
   - 不需要提供安装指引，除非用户主动询问

3. **如果没有现成 skill，给出自建方向**
   - 说明这个环节适合做成什么类型的 skill
   - 建议 skill 的核心功能和触发关键词
   - 评估制作难度（简单/中等/复杂）
   - **明确标注 AI 能做什么、不能做什么**：AI 负责信息收集/初稿生成/选项呈现，用户负责最终决策和审核
   - **标注数据时效性风险**：如果 skill 依赖实时数据（搜索量、热点趋势），需提醒用户验证数据新鲜度

### 第四步：输出诊断报告

使用以下模板输出：

```markdown
# AI 提效诊断报告：{岗位名称}

## 一、工作流梳理
| 环节 | 具体任务 | 时间占比（用户提供或估算） |
|------|----------|---------------------------|
| ...  | ...      | ...                       |

## 二、提效机会矩阵
| 环节 | 痛点 | 提效方案 | 推荐 Skill / 自建方向 | 预期节省 |
|------|------|----------|----------------------|----------|
| ...  | ...  | ...      | ...                  | ...      |

## 三、立即可用的 skill 推荐
1. **{skill 名称}** — {功能描述}
   - 适用环节：{环节名}
   - 来源：{已安装 / GitHub: xxx}

2. ...

## 四、建议自建的 skill（如无现成方案）
1. **{skill 构想名称}** — {解决什么问题}
   - 核心功能：{...}
   - 触发场景：{...}
   - 制作难度：{简单/中等/复杂}
   - AI 边界：{AI 负责什么，用户必须把关什么}
   - 数据风险：{如涉及实时数据，提醒验证时效性}

2. ...

## 五、优先级建议
按「投入产出比」排序，标出：
- 🟢 立即做（今天就能用）
- 🟡 短期做（本周内落地）
- 🔴 中期规划（需要自建 skill 或流程改造）
```

## 注意事项
- 如果用户只说了岗位没讲具体工作，先问 2-3 个关键问题，不要直接给通用模板
- 如果用户上传了文档，先读取文档内容，再结合文档梳理流程
- 推荐 skill 时尽量具体，不要泛泛地说"用 AI 写文案"，要指出具体哪个 skill 能做什么
- **预期节省的时间要合理，不要夸大；同时明确标注哪些环节 AI 只能辅助、不能替代**
- **对于脚本撰写、文案生成等创意 skill，提醒用户：AI 产出的是初稿/框架，需要人工注入品牌调性和人性化表达**
- **对于依赖实时数据的 skill（如热点追踪、搜索量分析），提醒用户验证数据新鲜度和准确性**
- 保持 actionable：每个建议都要让用户知道"下一步做什么"
- **优先级排序要尊重用户的实际痛点，不要按固定模板分配。如果用户明确说"选题最痛苦"，就把选题相关的 skill 放在最前面**
